# Гостевая корзина: хранение

Итерация 1. Новые таблицы `carts`, `cart_items`, `cart_attachments` добавлены тремя
версионируемыми миграциями `20261014000100` … `20261014000300`. Существующие заказы,
оплата, сертификаты, отправления и резервы на первом этапе не изменялись.
Общий checkout добавлен в итерации 3, см. [cart-checkout.md](cart-checkout.md).

## Правила

- Полное изделие: одежда/цвет/размер, поддерживаемая вышивка, фото и комментарий.
  Пока поддерживаются Patronus, Car, petFace; индивидуальная вышивка — отдельно.
- Количество одежды не смешивается с числом объектов вышивки: до 4 патронусов,
  до 5 мордочек, с дополнительной проверкой профиля изделия.
- Наличие и конфигурация цены проверяются при добавлении. **Остатки не изменяются
  и не резервируются**, цена не сохраняется как окончательная. Перед оформлением
  выполняются повторный серверный расчёт и атомарная проверка всего состава.
- Согласованный срок: 30 дней после последней успешной мутации. Идемпотентный
  повтор и чтение не продлевают срок. В точке истечения доступ уже закрыт.
- Ограничения защиты: до 20 активных позиций, до 20 одинаковых изделий на позицию,
  суммарно до 50 изделий, до 50 МБ фотографий в одной корзине. Файл — до 5 МБ;
  на позицию до 10 фото, для мордочек до 5. После 100 добавлений за жизнь одной
  корзины требуется новая корзина (учитываются tombstone-записи удалений).

## API

Все ответы `no-store`. Авторизация покупателя не требуется. При создании сервер
генерирует UUID и отдельную случайную 256-битную возможность доступа; в БД лежит
только SHA-256 токена. Токен не используется в URL и не относится к админскому JWT.
Потеря browser localStorage означает потерю доступа, но не публичность фотографий.

| Метод | Путь относительно `/api/cart` | Назначение |
| --- | --- | --- |
| POST | `/session` | JSON с `turnstileToken`, создать доступ |
| GET | `/:cartId` | Состав и срок хранения |
| POST | `/:cartId/items` | Multipart с изделием и `images` |
| PATCH | `/:cartId/items/:itemId` | Только JSON `quantity` |
| DELETE | `/:cartId/items/:itemId` | Удалить позицию и её фото |
| DELETE | `/:cartId` | Очистить всю корзину |
| GET | `/:cartId/items/:itemId/attachments/:attachmentId` | Закрытое скачивание фото |

Для всех путей, кроме создания, обязателен `X-Cart-Access-Token`. UUID сам по себе
не даёт доступа. Новое изделие требует `Idempotency-Key` (стабильный UUID v4).
При совпадении ключа и содержимого возвращается существующая позиция; другое
содержимое или повтор удалённой позиции — 409. Хеш включает параметры и байты
всех фото, но не одноразовый токен CAPTCHA. Доступ другого владельца закрыт.

Multipart-поля: `productType`, `color`, `size`, `embroideryType`, `patronusCount`,
`petFaceCount`, `comment`, `privacyConsent=true`, `turnstileToken`, `images`.
Согласие проверяется до сохранения и фиксируется серверным временем в позиции.
Цены, imageUrl, inventoryId, покупатель и доставка от клиента здесь не принимаются.

Origin-проверка, Redis/IP rate limit и прежние whitelist/MIME/magic bytes/лимиты
изображений сохранены. Создание требует Turnstile; его успешная проверка даёт
одноразовый допуск к первой загрузке в течение 5 минут. Он расходуется в транзакции
после успешного сохранения. Каждое следующее новое изделие требует нового токена;
идемпотентный повтор не требует повторно расходовать уже использованный токен.
Загрузка без действующего доступа отвергается до обработки файлов. Прямой
`/uploads` остаётся закрыт. Доставка фото — через контроллер, private/no-store,
nosniff, с проверкой принадлежности позиции и вложения.

## Очистка и эксплуатация

Итерация 2 расширяет снимок корзины предварительными серверными ценами:
`unitPrice`, `linePrice`, `pricingError`, `stockWarning` в позиции и
`merchandisePrice` в корне. Используются действующие профили/доплаты; цена
не фиксируется в БД. При недоступной позиции или нарушенном новом лимите
сумма равна `null`, но сами позиции доступны для удаления. Наличие учитывает
все конфигурации одной складской позиции. Это оценка **без доставки**,
не основание для списания или резервирования. Общий checkout описан отдельно.
Возвращается также несекретный UUID `requestKey` для сопоставления успешно
сохранённого изделия, если браузер потерял ответ. Хеш содержимого и токен
доступа по-прежнему не попадают в DTO.

Фото хранятся в `<UPLOAD_DIR>/carts/<cart UUID>/<item UUID>`, отдельно от фотографий
оформленных заказов. Сохранение файлов и записей выполняется под блокировкой
корзины. Ошибка БД откатывает запись и убирает уже перемещённые файлы.

Удаление позиции оставляет маленькую запись для защиты от повторного добавления;
фото удаляются, `filesPurgedAt` фиксируется только после успеха. При ошибке очистка
повторяется. При запуске и ежечасно на 17-й минуте сервер очищает просроченные
корзины и удалённые вложения, пакетами до 100. Блокировки БД защищают от параллельных
воркеров. Пути проверяются, symlink-каталоги не обходятся; очистка не удаляет широкие
деревья. Остатки прерванных загрузок удаляются только внутри конкретной просроченной
UUID-корзины и с проверкой имён. Ошибки оставляют запись для повторной обработки.

Перед развёртыванием нужны `npm run db:migrate`; новые секреты или настройки `.env`
не нужны. Оплата нескольких позиций, независимые копии фото заказа, доставка и скидка
сертификата реализованы в итерации 3. Оплаченный заказ не зависит от срока корзины.

Проверки: `npm test`, `npm run lint`, `npm run test:migrations`. Последняя команда
создаёт изолированную временную БД, проверяет реальные корзины/HTTP/файлы,
конкурентные добавления, откат, отсутствие списания остатков, удаление, доступ
владельца, expiry, затем откат и повторное применение миграций. Она не меняет
рабочую БД. `verify-cart-storage.js` отдельно отказывается работать без имени
тестовой базы заданного формата. Изображения тестов создаются во временной папке.
