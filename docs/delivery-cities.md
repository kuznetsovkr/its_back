# Подтверждённый город получения

## Окружение перед деплоем

Добавить `DADATA_API_KEY` — токен API DaData «Подсказки» (совместимый alias: `DADATA_TOKEN`). Можно использовать уже имеющийся токен адресных подсказок. Не публиковать значение в Git/логах. Production startup gate не пропускает запуск без ключа: это предотвращает выкладку оформления с неработающим выбором города. При ошибке/недоступности самого провайдера API возвращает понятную ошибку 503.

Для подписи выбора используется отдельный purpose-derived HMAC-ключ от существующего `ORDER_ACCESS_SECRET`; новый секрет и миграции БД не требуются. Смена этого секрета инвалидирует сохранённые выборы.

## Контракт

POST JSON, доверенный Origin в production, общий Redis-backed IP-лимит 120 запросов за 15 минут:

- `/api/delivery/cities/suggest`: `{query}` (2–120 символов), до 7 подсказок `{id,name,label}`.
- `/api/delivery/cities/resolve`: `{id}` — UUID ФИАС выбранного населённого пункта. Сервер вызывает DaData по ID и возвращает `{city}` с координатами и подписанным `token` на 30 дней.
- `/api/delivery/cities/office`: `{officeCode}` — сервер повторно получает ПВЗ у СДЭК и возвращает `{city}`. Клиентские названия/координаты не принимаются.

DaData ограничена Россией, городами и населёнными пунктами (включая федеральные города с уровнем ФИАС 1). Нельзя выбрать улицу/дом или регион вместо города. Самовывоз разрешает только Красноярск, подтверждённый DaData либо СДЭК (код 278).

Серверный ограниченный кэш: запросы 5 минут, ФИАС 24 часа, ПВЗ 5 минут; до 1000 записей/100 одновременных загрузок с объединением одинаковых запросов. DaData timeout 7 секунд. В HTTP-ответах `no-store`. Секреты/upstream-ошибки наружу не выводятся.

## Сохранение заказа

Фронтенд передаёт `deliveryCityToken`, а не свободное название. Для Почты и самовывоза `/orders/create` проверяет подпись и срок; самовывоз вне Красноярска отклоняется. Для СДЭК реальный город берётся из серверного ПВЗ, даже в индивидуальной заявке без цены. Старый `manual` без token поддержан для совместимости, но не разрешает самовывоз.

Используется существующий `orders.deliveryCity`; адрес самовывоза по-прежнему задаёт сервер. Ни тарифы, ни создание отправлений, ни применение сертификата к доставке не меняются. Корзина по-прежнему получает город из серверного ПВЗ.

## Проверки

`npm test`, `npm run lint`. Тесты `deliveryCities`, `requestValidation`, `orderDeliveryRoutes` проверяют подпись/истечение/подмену, границы DTO, ограничения/кэш, Origin/rate limit, запрет самовывоза другого города и сохранение канонического города. Внешние API подменены.

Контракт DaData: [подсказки адресов](https://dadata.ru/api/suggest/address/), [поиск адреса по ФИАС](https://dadata.ru/api/find-address/).
