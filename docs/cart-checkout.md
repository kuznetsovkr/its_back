# Оформление и оплата гостевой корзины

Один `orders` с флагом `isCartOrder`, неизменяемые позиции в `order_items`, один получатель,
расчёт СДЭК и один счёт PayKeeper. Старый одиночный заказ и отдельные индивидуальные
заявки сохраняют прежний путь. Custom/надпись с неизвестной ценой не допускаются в корзину.

## API

Пути относительно `/api/cart`, требуют `X-Cart-Access-Token`, доверенный Origin,
rate limit, строгий JSON и возвращают `no-store`.

- `POST /:cartId/quote`: `{revision, officeCode, certificateCode}`. Читает серверные
  цены/остатки/профили, проверяет ПВЗ и получает тариф. Возвращает `quoteHash`, стоимость
  изделий, доставки, скидку, доплату и тестовый режим. Ничего не резервирует.
  Каждая единица одежды — отдельное место СДЭК (согласовано).
- `POST /:cartId/checkout`: те же поля + `quoteHash`, `buyer`, `turnstileToken`;
  `Idempotency-Key` UUID обязателен. Цены, позиции и габариты от клиента запрещены.
  Телефон другого получателя обязателен при отдельном ФИО; иначе используется покупатель.
- `POST /:cartId/checkout/cancel`: пустой объект. Отменяет только неоплаченный заказ,
  освобождает остатки/сертификат, разблокирует корзину, не удаляет изделия/фото.
- `GET /:cartId`: теперь возвращает `revision`, а при начатой оплате — `checkout` с
  контактами, ценовым снимком, составом и свежим scoped order token для продолжения оплаты.

Изменение состава увеличивает ревизию. Старая вкладка/устаревший расчёт получают 409
с понятным сообщением. Начатая оплата блокирует изменения. Повтор создания с тем же
ключом/содержимым возвращает тот же заказ; CAPTCHA повторно не расходуется.
Другой запрос под старым ключом отклоняется. Доступы не передаются в URL.

## Деньги, остатки и файлы

В одной транзакции: блокировка корзины и складских строк в стабильном порядке,
повторная проверка цены/состава, создание позиций, агрегированные резервы по `inventoryId`,
резерв сертификата и связь `cart_checkouts`. Один сертификат покрывает только изделия
с вышивкой, не доставку. Конкурирующие корзины не могут потратить один остаток/баланс дважды.
Срок резерва — прежний `ORDER_RESERVATION_TTL_MINUTES` (по умолчанию 30 мин).

Фотографии проверяются и копируются в закрытый каталог заказа с правами 600;
`order_attachments.orderItemId` сохраняет соответствие изделию. Оригиналы не перемещаются.
При подтверждённом откате новые копии убираются; при неизвестном результате COMMIT
сохраняются до проверки, чтобы не удалить файлы принятого заказа.
Очистка корзины по TTL не затрагивает копии заказа.

PayKeeper использует один родительский orderId и прежнюю защиту повторной выдачи счёта.
Подтверждение оплаты атомарно фиксирует все резервы, списывает сертификат один раз
и помечает оплаченный состав удалённым. Повторный callback не дублирует списания/уведомления.
Нулевая доплата проходит существующее завершение сертификатом. Истечение резерва/отмена
освобождают весь состав. Запоздалая оплата отменённого/просроченного заказа требует ручной
проверки, не собирает новый заказ автоматически. Возвраты/компенсации остаются ручными.

В `order_shipments.packages` фиксируются габариты/вес каждого места на момент заказа.
Создание накладной автоматически **не включается** (`ENABLE_CDEK_AUTO_SHIPMENT=0`).
Общая онлайн-оплата пока только с ПВЗ СДЭК: для Почты/самовывоза ожидаются правила тарифов.
Telegram и защищённый API заказа передают все позиции, количества, цены и привязанные фото.

## Выкатка и проверки

Перед запуском нового кода выполнить `npm run db:migrate` (штатный deploy это делает).
Миграции `20261015000100` … `20261015000700` не удаляют старые заказы; новая уникальность
резервов — `(orderId, inventoryId)`. Новые секреты не требуются.

Откат на пустой тестовой БД проверен. Down-миграции отказывают при наличии реальных
групповых заказов/снимков: после начала работы нужен forward-fix или согласованное
восстановление резервной копии, а не удаление финансовых данных.

`npm test`, `npm run lint`, `npm run test:migrations`. Последняя команда создаёт временную
PostgreSQL БД и проверяет реальные транзакции, HTTP, закрытые фото, миграции up/down/up,
конкуренцию за товар/сертификат, откат копирования, отмену/expiry, повторный счёт
и подписанные callbacks. PayKeeper, Telegram и тариф СДЭК в тестах имитируются:
реальные платежи и отправления не создаются.
